# 概要设计

> 状态：草案 v0.1　|　范围：整体架构、模块划分、关键机制、里程碑
> 素材管线的细节见 [asset-pipeline.md](asset-pipeline.md)。

## 1. 目标

在 Godot 4 上做一款**红警 2 世界观的基地防守型塔防**：玩家在一座基地中采矿、供电、建造防御设施，抵御分波次从地图边缘涌入的敌军，并用超级武器作为战略手段。

同时把**引擎层做成通用的**：它不知道"红警"、"塔防"、"盟军"，只提供模拟、数据、寻路、战斗、经济、等距渲染、UI 等通用能力。红警内容全部落在游戏层和素材包里。

### 非目标（第一版）

- 不做多人联机、不做存档回放（但模拟层保持确定性，为以后留口子）
- 不做 RTS 式的己方单位微操
- 不做 3D 渲染；不用 Rust / GDExtension
- 不维护单元测试（见 §2），靠"运行验证 + 静态规则检查"推进

## 2. 约束

| # | 约束 | 落地方式 |
|---|------|----------|
| C1 | **每个源文件 ≤ 2000 行（硬约束）** | `tools/check_rules.py` 检查，`make check` 与提交前必跑；超过 1500 行即告警，应拆分 |
| C2 | 全 GDScript（Godot 4.x），开启静态类型 | 所有变量、参数、返回值写类型 |
| C3 | 素材加载与玩法逻辑分离 | 逻辑只认 `asset_id` 字符串；专有格式只出现在 `tools/` |
| C4 | 引擎通用、高内聚低耦合 | 分层依赖规则（§3.2）由脚本静态检查 |
| C5 | 解包尽量用开源工具 | 见 asset-pipeline.md |
| C6 | 前期不写单元测试 | 保留可测性设计（纯逻辑、无节点依赖），以后可补 |
| C7 | 原版素材不入库、不分发 | `.gitignore` 排除；素材加载层可整体替换 |

## 3. 总体架构

### 3.1 分层

```
┌────────────────────────────────────────────────────────────┐
│ tools/   离线素材管线（Python + 开源工具）                  │
│          原始素材 ──► 中立素材包（PNG/OGG/JSON）            │
└───────────────────────────┬────────────────────────────────┘
                            │ 仅通过 manifest.json 这一个契约
┌───────────────────────────▼────────────────────────────────┐
│ godot/src/app      启动、场景装配、主菜单、关卡流程          │
├────────────────────────────────────────────────────────────┤
│ godot/src/game     红警塔防的规则与内容：波次、防御塔、       │
│                    敌人、超级武器、关卡、专属 HUD             │
├────────────────────────────────────────────────────────────┤
│ godot/src/engine   通用引擎：core / data / assets / sim /    │
│                    spatial / nav / combat / economy /        │
│                    view / ui / audio / input                 │
└────────────────────────────────────────────────────────────┘
```

### 3.2 依赖规则（由 `check_rules.py` 强制）

1. `app → game → engine`，**只能向下依赖，禁止反向**。
2. `engine` 内部各模块的依赖见 §4 的模块表，不得成环。
3. 模块之间优先通过 **EventBus 事件**、**Command 命令**和 **接口基类**通信，不直接伸手进对方内部状态。
4. `engine` 不得出现任何红警专有名词、硬编码单位名或素材路径。
5. 只有 `engine/assets` 允许读取素材包文件；其他层拿到的都是已加载的 `SpriteSet`、`AudioBank` 等对象。

### 3.3 目录结构

```
war-defence/
├─ AGENTS.md  README.md  Makefile  .gitignore  .editorconfig
├─ docs/                      # 设计文档
├─ tools/                     # 离线工具（素材管线、规则检查），不进 Godot 工程
│  ├─ check_rules.py          # 行数 + 分层依赖检查
│  └─ asset_pipeline/         # 解包/转换脚本（见 asset-pipeline.md）
├─ third_party/               # 外部开源工具的下载/构建位置（git 忽略）
├─ 尤里科技时代4.0完结版/      # 原始素材（git 忽略；路径可通过配置覆盖）
└─ godot/                     # Godot 工程根（project.godot 在此）
   ├─ src/
   │  ├─ engine/              # 通用引擎（§4）
   │  ├─ game/                # 红警塔防内容（§6）
   │  └─ app/                 # 启动与装配
   ├─ content/                # 手写/生成的数据定义（JSON，入库）
   │  ├─ defs/                # 单位、建筑、武器、弹头、护甲…
   │  └─ levels/              # 关卡、波次
   ├─ packs/                  # 管线产出的素材包（git 忽略）
   └─ scenes/                 # .tscn 场景
```

> Godot 工程放在 `godot/` 子目录，是为了让它**不会扫描**根目录下 1.5GB 的原始素材（其中的 `.wav` 等会被误导入）。

## 4. 引擎模块（`godot/src/engine/`）

| 模块 | 职责 | 依赖 |
|------|------|------|
| `core` | EventBus、服务定位器、日志、确定性 RNG、ID 生成、通用数学/容器 | — |
| `data` | 定义（Definition）注册表与加载；JSON → 类型化定义对象；校验 | core |
| `assets` | 素材包加载；`AssetProvider` 接口；`SpriteSet`、`AudioBank`；缓存 | core, data |
| `spatial` | 网格、等距↔逻辑坐标转换、空间哈希（范围查询） | core |
| `sim` | 世界（World）、固定步长循环、实体存储、System 基类、命令队列 | core, data, spatial |
| `nav` | 地形可通行性、**流场（Flow Field）** 寻路、阻挡与重算 | spatial, sim |
| `combat` | 武器、弹头、护甲倍率矩阵、弹道、索敌、伤害结算 | sim, spatial |
| `economy` | 资源钱包、采集循环、电力网络、生产/建造队列 | sim |
| `view` | 等距相机、精灵演员池、深度排序、特效、血条、地形渲染 | sim, assets, spatial |
| `audio` | 音效总线、语音、音乐、音频池 | assets |
| `input` | 输入映射、放置塔的预览与校验、命令生成 | sim, view |
| `ui` | 通用 HUD 控件、侧边栏建造菜单、主题 | assets, input |

关键点：**`sim` 及其下层不依赖任何 Node**，只用 `RefCounted` 与 Packed 数组，因此它与渲染完全解耦，也便于以后补测试或移植。

## 5. 关键设计

### 5.1 模拟与表现分离

- **模拟层**（`sim`/`nav`/`combat`/`economy`）以固定步长（如 30 tick/s）推进，使用 `engine/core` 的种子化 RNG，保证给定输入下结果可复现。
- **表现层**（`view`/`ui`/`audio`）每帧读取模拟状态并插值显示；通过 EventBus 订阅"单位死亡""开火"等事件来播特效和音效。
- **玩家输入只产生 Command**（如 `PlaceBuilding`、`Sell`、`FireSuperweapon`），入队后由模拟层在下一 tick 执行。表现层从不直接修改模拟状态。

### 5.2 数据驱动

- 所有单位、建筑、武器、弹头、护甲、科技树都是 **Definition**，存为 JSON，由 `data` 模块加载为类型化对象。
- 红警原版数值来自 `rulesmd.ini`：管线把需要的条目转换成 JSON 草稿（造价、血量、射程、武器、护甲倍率），人工校对后放入 `content/defs/`。**游戏运行时不解析 INI。**
- 实体 = ID + 一组组件。引擎提供通用组件（`Transform`、`Health`、`Mover`、`Weapon`、`PowerConsumer`、`Producer`……），游戏层只通过 Definition 组合它们，必要时扩展自己的组件。

### 5.3 素材抽象

- 逻辑只引用字符串 ID，如 `sprite: "allied.prism_tower"`、`sound: "sfx.prism_fire"`。
- `AssetProvider` 把 ID 解析成 `SpriteSet`：方向数、每方向帧数、动画（待机/行走/开火/死亡）、锚点、阴影、队伍色蒙版。
- 想换成自制素材，只需提供另一个符合 manifest 契约的素材包，**引擎和游戏代码零改动**。

### 5.4 等距坐标

- 逻辑世界是**正交网格**（x, y 为格坐标，浮点表示格内位置）。所有模拟都在逻辑坐标上做。
- `spatial/iso_projection` 负责逻辑坐标 ↔ 屏幕坐标。红警 2 的地形格是 2:1 菱形（约 60×30 像素），沿用此比例以便原版地形和精灵直接适配。
- 深度排序：按逻辑坐标 `x + y`（再加高度偏移）计算 `z_index`，由 `view` 统一管理。

### 5.5 寻路：流场

- 塔防里"很多敌人去同一个目标"，流场比逐个 A* 便宜得多：每个目标一张场，所有敌人查表前进。
- 玩家放置/出售建筑会改变可通行性，触发局部或整张场重算（节流，每 N tick 最多一次）。
- 敌人遇到建筑阻挡时的策略（绕路 / 攻击挡路的建筑）作为 `nav` 的可配置策略，由游戏层选择。

### 5.6 战斗

沿用红警的**弹头 × 护甲**机制：

- 每种武器引用一个弹头；弹头对每种护甲类型有伤害倍率（`Verses`）；目标有护甲类型。
- 伤害 = 武器基础伤害 × `Verses[弹头][护甲]` × 距离衰减（可选）。
- `combat` 只提供机制（索敌、冷却、弹道、结算）；具体数值全在定义里。

### 5.7 经济与电力

- **资源**：矿车采集 → 矿场结算。引擎的 `economy` 提供"采集者—资源点—结算点"的通用循环。
- **电力**：所有耗电组件登记到电网；供电 < 用电时，耗电设施按比例降效或停机（光棱塔等高耗电防御会瘫痪）。这是塔防里的核心取舍：电力即防线上限。
- **生产**：建造队列、前置科技检查、放置校验，全部走 Command。

### 5.8 性能策略（纯 GDScript）

GDScript 比原生慢，所以：

- 大量同类实体（敌人、弹丸）用 **SoA（结构体数组）**：`PackedVector2Array`、`PackedFloat32Array` 存位置/血量，系统按批遍历，避免每个敌人一个对象。
- 视觉上先用池化的 `Sprite2D`；出现瓶颈再换 `RenderingServer` 直接绘制或 `MultiMesh`，因为表现层与模拟层解耦，替换只影响 `view`。
- 索敌用空间哈希，避免 O(n·m)。
- 预算目标：**同屏 300 敌人 + 60 防御设施，60 FPS**（M5 验收）。

## 6. 游戏层（`godot/src/game/`）

游戏层只做三件事：**定义内容、编排规则、提供专属界面**。

| 子模块 | 内容 |
|--------|------|
| `rules` | 胜负条件、波次规则、难度参数、科技解锁节奏 |
| `waves` | 波次导演：读取关卡配置，按时间/事件在出生点生成敌人 |
| `content` | 注册本游戏的专属组件/系统（如心灵控制的反制） |
| `superweapons` | 超级武器：充能、瞄准、效果 |
| `hud` | 基于 `engine/ui` 搭出的红警风格侧边栏、雷达、电力条 |
| `levels` | 关卡脚本：地图、出生点、基地位置 |

### 6.1 第一版内容（只做盟军）

> 以下名称按原版红警 2 列出，**以 `rulesmd.ini` 实际数据为准**（该 mod 可能改过数值和单位），M0 阶段核对。

- **基地建筑**：建造厂（基地核心，被毁即败）、电厂、矿场、兵营/战车工厂（解锁与升级）
- **防御设施**：机枪碉堡（前期）、光棱塔（高伤害、耗电大）、爱国者飞弹（对空）、巨炮（对地重炮）
- **辅助**：裂缝产生器（致盲敌方）、维修设施
- **超级武器**：天气控制器（闪电风暴）；后期可加超时空类效果
- **敌人（苏联军）**：动员兵（轻甲、量大）、犀牛坦克（重甲）、V3 火箭（远程攻城）、基洛夫飞艇（空袭）、天启坦克（Boss 级）

### 6.2 一局的流程

1. 起始资金与一座建造厂，先造电厂和矿场
2. 倒计时后第 1 波，从地图边缘出生点进攻
3. 波间玩家扩建、升级、重新布防；科技随波次解锁
4. 每 N 波一个 Boss 波；扛过全部波次获胜，建造厂被毁失败

## 7. 工程化

- **规则检查**：`make check` 运行 `tools/check_rules.py`（单文件 ≤ 2000 行；引擎层不得引用游戏/应用层）
- **格式化**：约定使用 [gdtoolkit](https://github.com/Scony/godot-gdscript-toolkit) 的 `gdformat`（`make format`）
- **`Makefile`** 提供统一入口：`run`、`check`、`format`、`import-assets`
- **`AGENTS.md`** 给 AI 编码助手和新成员：目录、约束、命令、约定
- 提交规范、分支策略等随团队规模再补

## 8. 里程碑

| 阶段 | 内容 | 验收 |
|------|------|------|
| **M0 素材管线验证** | 解包 `.mix`；转出 1 个静态建筑（光棱塔）、1 个有方向的单位（灰熊/犀牛）、调色板、`rulesmd.ini` 数值；产出 manifest | Godot 里能显示这两个东西 |
| **M1 引擎骨架** | `core` / `data` / `assets` / `spatial` / `view` 基础；等距地图、相机、网格 | 能渲染等距地图并拖动、缩放 |
| **M2 模拟与战斗** | `sim` / `combat`：敌人沿直线走、防御塔索敌开火、伤害结算 | 一座塔能打死一队敌人 |
| **M3 寻路与放置** | `nav` 流场 + `input` 放置塔、出售；阻挡重算 | 放塔后敌人会绕路/攻击挡路建筑 |
| **M4 经济与电力** | 矿车采集、电力网络、建造队列、侧边栏 | 缺电则光棱塔降效 |
| **M5 波次与内容** | 波次导演、全部第一版内容、超级武器、胜负 | 可完整通关一张图；性能预算达标 |
| **M6 打磨** | 音效音乐、特效、关卡增多、主菜单、素材包可替换性验证 | 用占位素材包也能跑 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 该 mod 的 `.mix` 非标准（加密/自定义），开源工具解不开 | 素材管线卡住 | M0 第一件事就是验证；备选自己用 Python 实现 MIX 读取（格式公开） |
| VXL 体素没有现成的"导出精灵序列"工具 | 单位美术缺失 | 自写 VXL+HVA 读取与正交渲染，输出 N 方向 PNG；或先用 SHP 精灵（建筑、步兵）跑通 |
| GDScript 性能不够 | 大规模敌人掉帧 | SoA + 空间哈希 + 表现层可替换；最坏情况把 `nav`/`combat` 热点按接口换成 GDExtension |
| 引擎"通用"过度设计 | 拖慢进度 | 只抽象第二个游戏**一定会用到**的部分；不确定的先放游戏层，重复出现再上提 |
| 版权 | 无法公开发布 | 素材加载层隔离；发布版换自制素材包 |

## 10. 已定决策

| # | 问题 | 决策 | 理由 |
|---|------|------|------|
| D1 | 敌人被建筑挡路 | **能绕则绕；完全封死时攻击挡路建筑**。玩家允许封路（不做放置禁止），由 `nav` 的阻挡策略接口实现，游戏层选用该策略 | 保留"迷宫塔防"的策略深度，又不会出现敌人卡死；符合原作 AI 行为 |
| D2 | 迷雾 | **第一版不做** | 防守型塔防信息透明更利于决策；后续可作为 `view` 的可选层 |
| D3 | 地图来源 | **自制关卡 + 原版地形图块**，不直接解析 `.yrm` 的地图对象 | `.yrm` 含大量地图对象与触发器，解析成本高且与塔防无关 |
| D4 | mod 的"科技时代"新单位 | **第一版只做原版盟军核心单位**；mod 新增单位在 M5 后通过新增 Definition 追加 | 控制范围；数据驱动设计下追加不改代码 |
